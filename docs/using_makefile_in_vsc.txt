Configure VS Code build task

You already have a tasks.json — open it (.vscode/tasks.json).
If it doesn’t exist yet, create it manually.

Replace its contents with this 👇

Example tasks.json for Makefile build (Windows / MinGW)


{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "Build project (Makefile)",
            "type": "shell",
            "command": "make",
            "args": [],
            "group": {
                "kind": "build",
                "isDefault": true
            },
            "problemMatcher": ["$gcc"],
            "options": {
                "cwd": "${workspaceFolder}"
            }
        },
        {
            "label": "Clean project",
            "type": "shell",
            "command": "make",
            "args": ["clean"],
            "group": "none",
            "problemMatcher": [],
            "options": {
                "cwd": "${workspaceFolder}"
            }
        }
    ]
}


| Field                                 | Meaning                                                    |
| ------------------------------------- | ---------------------------------------------------------- |
| `"command": "make"`                   | Run the GNU Make program available in your PATH            |
| `"args": []`                          | No arguments → executes the default target (`all`)         |
| `"group"`                             | Integrates with VS Code’s build system (Ctrl + Shift +B)   |
| `"problemMatcher": ["$gcc"]`          | Highlights compiler errors/warnings directly in the editor |
| `"options.cwd": "${workspaceFolder}"` | Run make in the project’s root directory                   |

What that message means

mingw32-make: *** No targets specified and no makefile found.  Stop.


It means:

The command make (or mingw32-make) didn’t find a file named Makefile (or makefile) in the current working directory where it was executed.

So VS Code is running make, but in the wrong folder — or your Makefile has a different name or location.


Step 2 — Check tasks.json working directory

Open .vscode/tasks.json and confirm that the "cwd" option points to your project root:

"options": {
    "cwd": "${workspaceFolder}"
}


This tells VS Code to run make in the same folder where your Makefile lives.

If you have your sources in a subfolder (e.g. src/), but the Makefile is at the root, you still want this to be ${workspaceFolder}.

Step 3 — Verify in the VS Code terminal

Open the VS Code terminal (`Ctrl+``) and run:

dir Makefile      # on Windows
# or
ls Makefile       # on Linux / WSL


If the file isn’t found, you’re in the wrong directory.

Then try:

make


If that builds successfully, VS Code will work once "cwd" is correct.


tep 4 — Ensure make is installed and available

The tool might be named mingw32-make.exe instead of make.exe.

Try this in the VS Code terminal:

where make

Excellent question — you’re very close!

No, you can’t use ${workspaceFolder/src} — that syntax isn’t valid in VS Code’s task configuration.
But you can absolutely tell VS Code to run make inside your src folder — it just takes a slightly different form.

Let’s fix it properly 

Correct way: use "cwd" pointing to src

In your .vscode/tasks.json, modify the build task like this:

{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "Build project (Makefile in src)",
            "type": "shell",
            "command": "mingw32-make",
            "args": [],
            "group": {
                "kind": "build",
                "isDefault": true
            },
            "problemMatcher": ["$gcc"],
            "options": {
                "cwd": "${workspaceFolder}/src"
            },
            "detail": "Run Makefile located in src/"
        }
    ]
}

This line:

"cwd": "${workspaceFolder}/src"


tells VS Code to change directory into your src/ folder before running make.

| Field                      | Meaning                                           |
| -------------------------- | ------------------------------------------------- |
| `"cwd"`                    | “current working directory” for the build command |
| `"${workspaceFolder}"`     | The root folder you opened in VS Code             |
| `"${workspaceFolder}/src"` | A valid relative path to your Makefile            |


So VS Code runs:

cd src && mingw32-make


automatically when you press Ctrl + Shift + B.


Alternative: keep cwd at root but specify the path in args

If you prefer to leave the working directory as your project root, you can also tell make where the Makefile is:

"command": "mingw32-make",
"args": ["-C", "src"]


That’s equivalent to:

mingw32-make -C src


and works even if you have multiple Makefiles (e.g. one in src/, one in tests/).

Recommended options:

| Option                            | Works? | Description                                      |
| --------------------------------- | ------ | ------------------------------------------------ |
| `"cwd": "${workspaceFolder}/src"` | ✅      | Simple, clean, recommended                       |
| `"args": ["-C", "src"]`           | ✅      | More flexible if you want multiple build folders |
| `"${workspaceFolder/src}"`        | ❌      | Invalid syntax                                   |
